# OpenCode 免费模型渠道连通性检测 (opencode-probe)

用于全面体检 `opencode2zcode` 插件接入的所有 OpenCode 免费渠道状态，提供客观实测证据与行动建议。

## 适用场景

当遇到以下情况时使用此技能：
1. 用户要求检测或测试 OpenCode 免费模型的可用性（或输入 `/opencode-probe`）。
2. 用户遇到某个免费模型报错（如 `Endpoint is unavailable`、`Model is not supported`、`RegionError` 等），需要排查是上游故障、地区限制还是本地网络问题。
3. 用户询问「为什么列表中多出某个模型（如 `exo-free`）但调不通」。
4. 用户想知道当前所有免费模型中，哪些可以直接用、哪些需要代理、哪些已经失效。
5. 用户想挑模型（哪个上下文大、哪个值得长期用）。

---

## 执行步骤

### 步骤 1：运行连通性探针

优先通过 Bash 运行探针脚本：

```bash
node D:/Projects/opencode2zcode/tools/probe-channels.mjs
```

如只需测试特定模型，可传入参数：
```bash
node D:/Projects/opencode2zcode/tools/probe-channels.mjs --model exo-free
```

如需以结构化 JSON 分析：
```bash
node D:/Projects/opencode2zcode/tools/probe-channels.mjs --json
```

若本地代理未运行（探针会提示 41930 未就绪），执行拉起命令：
```bash
D:/Projects/opencode2zcode/bin/opencode2zcode.exe --ensure
```

### 步骤 2：对异常状态严格归因分类（核心判据）

检测结果必须严格区分以下根本原因，不得含糊笼统地归为“模型坏了”：

| 错误分类 | 特征特征识别 | 根本原因 | 行动与处方（说人话） |
| :--- | :--- | :--- | :--- |
| **✅ 正常可用 (ACTIVE)** | HTTP 200，成功返回有效生成文本 | 推理节点正常，通道畅通 | 可在 ZCode 模型选择器中作为主力模型放心使用。 |
| **🌍 网络位置/地区拒绝服务 (REGION_BLOCKED)** | 返回包含 `RegionError` / `This model is not available in your country` / `Country not allowed` | **出口 IP 地理位置限制**。上游模型服务商限制中国大陆等特定区域直连，并非模型下线或失效。 | **换节点即可用**。切换系统代理至支持的海外区域（香港、新加坡、美国、日本等），再次测试即可恢复。 |
| **🚫 本身已下架/已废弃 (CHANNEL_REMOVED)** | HTTP 410 (`ModelDeprecated`), HTTP 401 (`Model is not supported`), HTTP 400 (`Model is unavailable`) | **官方永久下线**。上游已终止该免费渠道，或模型已被彻底下架/废弃。 | **换任何节点都无解**。该渠道已失效，建议在模型列表忽略，不用浪费时间调试代理。 |
| **⏳ 端点未就绪/临时限流 (ENDPOINT_NOT_READY)** | HTTP 429 或 `Endpoint is unavailable` / `Rate limit exceeded` / HTTP 503 | **官方尚未接通推理服务**（如刚发布 Preview 的 `exo-free`），或触发了 IP 级并发限流 | **属于临时状态**。若为刚上架预览模型说明后端集群尚未开机，等官方接入；若为限流稍等几分钟后重试。 |
| **🔒 门禁伪装拦截 (GATE_FAILED)** | HTTP 403 `FreeTierError` / `OpenCode's free tier can only be used from within OpenCode` | 客户端身份伪装未通过 | 检查代理是否已注入 `bash`/`read` 门禁工具桩。 |
| **🔌 本地代理未就绪 (PROXY_UNREACHABLE)** | 127.0.0.1:41930 连接被拒 | 本地后台回环代理未启动 | 运行 `opencode2zcode.exe --ensure` 或双击启动器。 |

### 步骤 3：档位与选型参考（帮用户挑模型）

探针报告是一张表，五列：**模型 ID | 状态及核心诊断 | 上下文 | 档位 | 社区热度**。
插件已经配好的参数（最大输出、推理档位、图像、工具调用）不需要用户关心，不在表里。
**不报延迟**——单次测试的耗时随机性太大，没有参考价值。

向用户汇报时，必须遵守以下口径，**不得夸大**：

1. **档位只看"现在能不能调通"，不评价模型聪明不聪明。**
   S 闭眼用，A 换节点用，B 过阵子再试，C 别浪费时间。
2. **「社区热度」是 OpenRouter 全站真实调用量**（655 个模型的日榜），用的人多
   说明生态成熟、踩坑的人多。但**热度高不等于能力强**，只是个第三方佐证。
   对不上的（榜单里没有对应基座）显示"—"，不扣分、不降级，只是不佐证。
3. **参数相同的两个模型能力可能天差地别。** 不要按上下文或档位给模型排能力高低。
   用户问"谁更强"时，拿热度当参考，同时明说这只是调用量不是跑分。
4. **LMArena 这类竞技场榜单对不上 Zen 免费模型。** 它们全是各家厂商模型的
   免费/预览变体，榜单上没有同名条目，不要硬蹭。

档位定义：

| 档位 | 含义 | 行动 |
| :--- | :--- | :--- |
| **S 主力可用** | 实测畅通 | 直接用 |
| **A 换节点可用** | 地区受限，模型本身没问题 | 换代理节点 |
| **B 暂不可用** | 端点未就绪或限流，临时状态 | 过阵子再试 |
| **C 当前不可用** | 已下架、门禁拦截、需真实 key 等 | 别浪费时间 |

另外有一种情况要主动提醒：**目录已标废弃但实测仍通**的模型（报告里状态后带
`⚠️目录已废弃`）。现在能调，但上游随时会撤，不建议作为长期依赖；它们也不在
ZCode 的模型列表里——宁可少给，不给随时会失效的。

---

### 步骤 4：输出诊断报告

向用户汇报时，采用以下清晰规范呈现：
1. **一句话 TLDR**：当前共探测 N 个模型，X 个 S 档，Y 个 A 档，Z 个 B 档，W 个 C 档。
2. **一张表搞定**（探针报告本身就是这个格式，直接转述即可）：
   模型 ID | 状态及核心诊断 | 上下文 | 档位 | 社区热度
   按档位 S → A → B → C 排序。**不报延迟**（单次测试随机性太大，没有参考价值）。
3. **行动建议**：按档位分组说，重点讲 S 档里上下文大的；C 档要说清"别浪费时间"和处方。
4. 主动提醒：**目录已标废弃但实测仍通**的模型（状态后带 `⚠️目录已废弃`）现在能调但随时会撤，不建议长期依赖。
